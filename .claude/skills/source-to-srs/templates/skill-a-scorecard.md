## 3. 功能覆盖度

### 3.1 评分标准

| 分数 | 标准 |
|---:|---|
| 5 | 核心功能、边界功能、明确排除项均完整明确，无明显漏抽或误纳入。 |
| 4 | 核心功能完整，少量边界功能描述不足或排除项不够清晰。 |
| 3 | 核心功能基本覆盖，但存在明显遗漏或范围表达不稳定。 |
| 2 | 多个核心功能缺失，或相邻模块被明显误纳入。 |
| 1 | 模块范围严重错误，SRS 不可作为目标模块需求文档使用。 |

### 3.2 检查清单

- [ ] 已覆盖 scope confirmation 中的最终纳入范围。
- [ ] 已说明明确排除范围。
- [ ] 未把待确认相邻能力误写成核心需求。
- [ ] 查询、详情、新增、编辑、删除、批量、导入导出、状态流转等适用功能未漏掉。
- [ ] FR 编号与功能范围一致。

## 4. 源码准确度

### 4.1 评分标准

| 分数 | 标准 |
|---:|---|
| 5 | SRS 与源码事实高度一致，关键结论均有 evidence 支撑。 |
| 4 | 存在轻微表述偏差，但不影响需求理解和后续使用。 |
| 3 | 存在部分误读或依据不足，但核心规则未写反。 |
| 2 | 多个功能或规则与源码不一致，需要较大修改。 |
| 1 | 大量编造、关键规则写反或事实来源不可审计。 |

### 4.2 检查清单

- [ ] 每个主要 FR 有源码依据。
- [ ] 字段规则与 DTO / VO / Entity / Service 一致。
- [ ] 权限规则与权限注解或配置一致。
- [ ] 异常规则与错误码和抛出逻辑一致。
- [ ] 未把 reference_srs 或 domain_hints 当成源码事实。

## 5. 规则完整度

### 5.1 评分标准

| 分数 | 标准 |
|---:|---|
| 5 | 字段、业务、权限、异常、验收规则完整，关键约束均覆盖。 |
| 4 | 主要规则完整，少量边界规则描述不足。 |
| 3 | 规则基本可用，但字段、权限、异常或验收存在明显缺口。 |
| 2 | 多类关键规则缺失，影响后续测试生成或知识库使用。 |
| 1 | 规则层严重缺失，文档仅停留在功能列表。 |

### 5.2 检查清单

- [ ] 字段必填、长度、格式、枚举、默认值、唯一性等规则已覆盖。
- [ ] 业务校验、状态变更、删除限制、导入导出处理已覆盖。
- [ ] 权限规则已覆盖。
- [ ] 异常处理和错误码已覆盖。
- [ ] 验收标准覆盖正常路径、异常路径和边界路径。

### 5.3 扣分示例

- 漏掉关键字段唯一性：扣 1～2 分。
- 漏掉权限规则：扣 1～2 分。
- 漏掉核心异常处理：扣 1～2 分。
- 只有功能列表，没有验收标准：扣 2～3 分。
