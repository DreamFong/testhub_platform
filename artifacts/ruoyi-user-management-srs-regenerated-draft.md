# RuoYi-Vue-Pro 用户管理模块 Software Requirements Specification

Version: regenerated draft 0.1  
Status: source-derived draft  
Module: System Management / User Management

## 1 Introduction

### 1.1 Purpose

本文档定义 RuoYi-Vue-Pro 管理后台中用户管理模块的软件需求。文档从用户管理相关 Controller、Service、请求/响应对象、数据模型、错误码和权限菜单数据中逆向整理，用于支撑需求分析、测试用例设计、接口验证、RAG 知识库构建和自动化测试场景生成。

### 1.2 Scope

用户管理模块用于维护后台系统用户，支持后台用户的创建、查询、修改、删除、批量删除、密码重置、账号状态修改、用户导入、用户导出和启用用户精简列表获取。模块与部门、岗位、角色权限、租户账号配额、登录凭证和操作权限存在业务关联，但不负责部门、岗位、角色、菜单权限、第三方登录或前台会员用户本身的维护。

### 1.3 Definitions

| 术语 | 定义 |
|------|------|
| 后台用户 | 可以登录管理后台并使用后台功能的系统操作者。 |
| 用户账号 | 后台用户登录系统时使用的唯一账号。 |
| 用户昵称 | 后台用户在列表、详情和业务引用场景中的展示名称。 |
| 部门 | 用户所属组织节点，用户列表支持按部门及下级部门筛选。 |
| 岗位 | 用户承担的岗位职责，一个用户可以关联多个岗位。 |
| 角色 | 用户拥有的权限集合，决定可访问菜单、按钮和数据范围。 |
| 账号状态 | 用户是否允许正常登录和使用后台系统。 |
| 初始密码 | 用户导入时由系统配置提供的默认密码。 |

## 2 Overall Description

### 2.1 User Classes

用户管理模块主要面向超级管理员、系统管理员、普通运维人员和审计或只读人员。超级管理员拥有用户管理的完整能力；系统管理员在授权范围内维护后台用户；普通运维人员可在授权范围内查询或维护部分用户；审计或只读人员只能查看用户列表和详情，不允许新增、修改、删除、导入、导出或重置密码。

### 2.2 Product Perspective

用户管理模块是后台权限体系和组织协作能力的基础。后台用户数据会被角色授权、部门筛选、岗位关联、数据权限、操作日志和登录凭证等能力引用。因此，系统必须保证用户账号数据准确、唯一性校验可靠、状态变更及时生效、权限校验前后端一致，并能在日常运维中支持快速查询、维护和批量导入导出。

### 2.3 Business Process Overview

管理员进入用户管理页面后，系统展示用户列表，并允许通过账号、手机号、状态、创建时间、部门和角色等条件筛选用户。管理员可根据权限新增、编辑、删除、重置密码、修改账号状态、导入或导出用户。系统在保存前校验字段格式、唯一性、部门和岗位可用性以及租户账号数量限制，校验通过后持久化用户信息并刷新列表。

新增用户时，管理员必须填写用户账号、用户昵称和密码，可选择部门、岗位、手机号、邮箱、性别、头像和备注。系统默认将新增用户状态设置为正常。编辑用户时，普通编辑入口只更新基础资料和岗位关联，不更新密码。账号状态修改由独立功能完成。删除用户时，系统同时清理用户角色关联和岗位关联。用户导入时，系统使用配置中的账号初始密码作为默认密码，并逐条返回创建、更新和失败结果。

## 3 System Features

### 3.1 User Management Functional Requirements

#### 3.1.1 用户列表查询

FR-USER-001 系统应提供后台用户分页列表查询能力。查询条件包括用户账号、手机号码、账号状态、创建时间范围、所属部门和用户角色。按部门筛选时，系统应包含所选部门及其下级部门的用户。按角色筛选时，系统应先获取角色对应用户编号，再基于用户编号过滤结果。查询结果应分页展示，并按用户编号倒序排列；当无匹配数据时，系统应返回空分页结果。

#### 3.1.2 获取启用用户精简列表

FR-USER-002 系统应提供启用用户精简列表接口，用于前端下拉选择、负责人选择、用户分配等场景。该列表只返回账号状态为正常的后台用户，并附带部门信息用于展示。

#### 3.1.3 查看用户详情

FR-USER-003 管理员应能够查看单个后台用户详情。详情信息应包含用户编号、用户账号、用户昵称、备注、部门、岗位、邮箱、手机号、性别、头像、账号状态、最后登录 IP、最后登录时间和创建时间。当用户不存在时，系统应返回空结果。

#### 3.1.4 新增用户

FR-USER-004 管理员应能够新增后台用户。新增用户的必填字段包括用户账号、用户昵称和密码；可选字段包括备注、部门、岗位、邮箱、手机号、性别和头像。新增用户时，系统不允许通过创建请求设置初始账号状态，账号状态由系统默认设置为正常。用户密码应加密保存，不得明文持久化。

FR-USER-005 创建用户前，系统应校验当前租户账号数量是否超过租户账号配额；校验用户账号唯一性、手机号唯一性、邮箱唯一性；校验所选部门和岗位是否可用。用户账号重复时应阻止创建；手机号或邮箱重复时应阻止创建；部门或岗位不可用时应阻止创建。创建成功后，系统返回新用户编号，并保存用户与岗位的关联关系。

#### 3.1.5 编辑用户

FR-USER-006 管理员应能够编辑已有用户资料。可编辑内容包括用户账号、用户昵称、备注、部门、岗位、邮箱、手机号、性别和头像。普通编辑入口不应修改密码；账号状态也应通过独立状态修改功能完成。编辑时系统应校验用户存在、用户账号唯一性、手机号唯一性、邮箱唯一性，以及部门和岗位可用性。保存成功后，系统应更新用户资料并同步更新用户岗位关联。

#### 3.1.6 删除用户

FR-USER-007 管理员应能够删除单个用户或批量删除多个用户。删除单个用户前，系统应校验用户存在。删除成功后，系统应删除用户记录，并清理用户角色关联和岗位关联数据。批量删除时，系统应批量删除用户记录，并对每个用户清理角色关联和岗位关联。被删除用户不应继续出现在用户列表中。

#### 3.1.7 重置密码

FR-USER-008 管理员应能够为后台用户重置密码。重置密码时必须传入用户编号和新密码。新密码不能为空，长度必须为 4 到 16 位。重置前系统应校验用户存在，重置成功后系统加密保存新密码。重置密码不应改变用户其他基础资料。

#### 3.1.8 修改账号状态

FR-USER-009 管理员应能够修改后台用户账号状态。状态值必须符合系统通用状态字典和通用状态枚举。修改前系统应校验用户存在。用户被停用时，系统应删除该用户的后台 access token，使其不能继续使用后台功能。状态修改不应改变用户基础资料。

#### 3.1.9 用户导入

FR-USER-010 系统应提供用户导入模板下载能力。导入模板包含登录名称、用户名称、部门编号、用户邮箱、手机号码、用户性别和账号状态。管理员上传 Excel 文件后，系统读取用户数据并执行导入。

FR-USER-011 系统应支持用户批量导入，并允许管理员选择是否支持更新已存在用户。导入前，系统应校验导入列表不能为空，并读取配置项 `system.user.init-password` 作为导入用户默认密码。如果初始密码为空，系统应阻止导入。导入过程中，系统应逐条校验字段格式、手机号唯一性、邮箱唯一性、部门可用性等规则；新用户不存在时创建用户，已存在用户在允许更新时更新，不允许更新时记录失败。导入完成后，系统应返回创建用户列表、更新用户列表和失败明细。

#### 3.1.10 用户导出

FR-USER-012 管理员应能够按当前查询条件导出后台用户数据。导出时系统应取消分页限制，并输出用户编号、用户账号、用户昵称、部门名称、邮箱、手机号、性别、账号状态、最后登录 IP、最后登录时间等字段。

### 3.2 Page and Interaction Requirements

用户管理页面应提供用户查询、用户维护和批量操作入口。页面应支持按用户账号、手机号码、账号状态、创建时间范围、部门和角色筛选。操作区应根据当前登录用户权限展示新增、修改、删除、导入、导出、重置密码等操作入口。用户列表应展示用户编号、用户账号、用户昵称、部门名称、邮箱、手机号、性别、账号状态、最后登录信息、创建时间和操作按钮，并支持分页展示。

新增或编辑用户时，系统应展示用户账号、用户昵称、部门、岗位、邮箱、手机号、性别、头像、备注等表单字段。新增用户时必须填写密码；编辑用户时普通编辑入口不修改密码。删除用户和批量删除用户前应提供确认机制。导入用户时应提供模板下载、文件上传、是否允许更新已存在用户选项，以及导入结果反馈。

### 3.3 Data Requirements

| 字段 | 必填 | 规则和说明 |
|------|------|------------|
| 用户编号 | 修改/删除/详情/重置/状态修改必填 | 用户唯一标识。 |
| 用户账号 | 新增/编辑必填 | 由数字和字母组成，长度 4 到 30 个字符，系统内唯一。 |
| 用户昵称 | 新增/编辑必填 | 长度不超过 30 个字符，用于用户展示。 |
| 密码 | 新增/重置必填 | 长度 4 到 16 位；新增和重置密码时必填；不在列表或详情中明文展示。 |
| 备注 | 否 | 用户补充说明。 |
| 部门 | 否 | 如果选择部门，只能选择可用部门；用户列表支持按部门及子部门筛选。 |
| 岗位 | 否 | 可选择多个岗位；如果选择岗位，只能选择可用岗位。 |
| 邮箱 | 否 | 必须符合邮箱格式，长度不超过 50 个字符，填写后系统内唯一。 |
| 手机号码 | 否 | 必须符合手机号格式，填写后系统内唯一。 |
| 性别 | 否 | 使用系统性别字典值。 |
| 头像 | 否 | 用户头像地址。 |
| 账号状态 | 状态修改必填 | 新增用户默认正常；通过独立状态修改功能维护。 |
| 最后登录 IP | 系统维护 | 用于展示用户最后登录来源。 |
| 最后登录时间 | 系统维护 | 用于展示用户最后登录时间。 |
| 创建时间 | 系统维护 | 用于列表展示和创建时间范围筛选。 |

### 3.4 Business Rules

用户账号在系统内必须唯一。手机号和邮箱在填写后也必须唯一。用户账号只能包含字母和数字，长度必须为 4 到 30 个字符。用户昵称长度不能超过 30 个字符。密码长度必须为 4 到 16 位。

创建用户前，系统应校验当前租户账号数量是否达到租户配额上限。达到上限时禁止创建用户。新增用户状态默认为正常，不允许通过新增接口指定初始状态。用户密码应加密保存，不得明文展示。

编辑用户时不通过普通编辑入口更新密码。用户密码重置由独立功能完成，账号状态修改由独立功能完成。用户被停用后，系统删除该用户的后台 access token，使其不能继续使用后台功能。

删除用户时，系统应清理用户角色关联和岗位关联数据。批量删除时，应对每个被删除用户执行关联清理。用户列表按部门查询时，应包含所选部门及其下级部门。按角色查询时，应基于角色关联用户进行过滤。

导入用户时，导入数据不能为空，账号初始密码配置不能为空。导入过程逐条校验字段格式、唯一性和关联基础数据，并按创建、更新和失败分类返回结果。已存在用户只有在允许更新时才更新，否则记录失败。

### 3.5 Permission Requirements

| 权限场景 | 规则 |
|----------|------|
| 用户列表和详情 | 需要 `system:user:query` 权限。 |
| 新增用户 | 需要 `system:user:create` 权限。 |
| 修改用户和修改状态 | 需要 `system:user:update` 权限。 |
| 删除用户和批量删除用户 | 需要 `system:user:delete` 权限。 |
| 重置密码 | 需要 `system:user:update-password` 权限。 |
| 导入用户 | 需要 `system:user:import` 权限。 |
| 导出用户 | 需要 `system:user:export` 权限。 |
| 前后端一致性 | 页面入口应按权限展示，后端接口必须进行权限校验。 |

### 3.6 Error Handling and Messages

系统应在字段校验、唯一性校验、关联基础数据校验、导入文件校验、用户状态校验和权限校验失败时给出明确提示。错误提示应面向管理员可理解，避免泄露系统内部异常。

| 异常场景 | 系统处理 |
|----------|----------|
| 用户账号重复 | 阻止创建或保存，并提示用户账号已经存在。 |
| 手机号重复 | 阻止创建或保存，并提示手机号已经存在。 |
| 邮箱重复 | 阻止创建或保存，并提示邮箱已经存在。 |
| 用户不存在 | 查看详情返回空结果；编辑、删除、重置密码或修改状态时提示用户不存在。 |
| 导入用户数据为空 | 阻止导入，并提示导入用户数据不能为空。 |
| 初始密码为空 | 阻止导入，并提示初始密码不能为空。 |
| 用户密码校验失败 | 阻止密码修改，并提示用户密码校验失败。 |
| 用户已被禁用 | 阻止相关使用场景，并提示用户已被禁用。 |
| 超过租户账号配额 | 阻止创建用户，并提示超过租户账号配额。 |
| 部门不可用 | 阻止创建或编辑，并提示部门不可用。 |
| 岗位不可用 | 阻止创建或编辑，并提示岗位不可用。 |
| 字段格式不合法 | 阻止提交，并提示对应字段规则。 |
| 导入部分失败 | 在导入结果中展示失败用户和失败原因。 |

## 4 Non-functional Requirements

### 4.1 Security

用户管理相关操作必须受登录态和权限控制保护。密码必须加密保存，不得明文展示。停用用户时，系统应删除该用户的 access token。删除用户时，系统应清理角色和岗位关联数据。导入文件必须进行格式和内容校验，错误信息不得泄露系统内部异常。

### 4.2 Usability

系统应为查询、重置、导入、导出、创建、编辑和删除操作提供明确反馈。字段校验应尽量在提交前提示。批量删除和删除操作应提供确认机制。导入结果应区分创建成功、更新成功和失败明细，便于管理员修正后重新导入。

### 4.3 Performance and Maintainability

用户列表应分页加载，并按查询条件及时刷新。导出时可按当前查询条件导出全量数据。用户字段、状态、性别等基础数据应保持统一口径。导入模板字段应与系统用户字段保持一致。用户列表查询应支持按部门和角色过滤，以满足组织和权限维度的运维需求。

## 5 Acceptance Criteria

| 验收项 | 验收标准 |
|--------|----------|
| 用户列表 | 管理员可查看用户分页列表，并可按账号、手机号、状态、创建时间、部门和角色筛选；无结果时返回空分页结果。 |
| 启用用户精简列表 | 系统可返回状态正常的用户精简列表，用于下拉选择场景。 |
| 用户详情 | 管理员可查看用户详情；用户不存在时返回空结果。 |
| 新增用户 | 管理员填写账号、昵称和密码后可创建用户；状态默认为正常；账号、手机号、邮箱重复或字段格式不合法时阻止提交并提示原因。 |
| 编辑用户 | 管理员可修改用户基础资料和岗位关联；普通编辑不修改密码；保存成功后列表和详情展示最新数据。 |
| 删除用户 | 删除前校验用户存在；删除后用户从列表移除，并清理角色关联和岗位关联。 |
| 批量删除 | 可批量删除多个用户，并逐个清理角色和岗位关联。 |
| 重置密码 | 管理员输入合法新密码后可成功重置；密码为空或长度不符合规则时阻止提交。 |
| 修改状态 | 管理员可启用或停用用户；停用后系统删除用户 access token。 |
| 导入用户 | 可下载导入模板；可导入合法数据；导入空数据或初始密码为空时阻止导入；导入完成后返回创建、更新和失败明细。 |
| 导出用户 | 管理员可按当前查询条件导出用户数据。 |
| 权限控制 | 无对应权限的用户不能访问或执行对应操作。 |

## 6 Boundaries and Exclusions

用户管理模块只维护后台系统用户，不维护前台会员用户。角色分配、角色权限、菜单权限、部门维护和岗位维护由对应模块负责。用户管理模块只引用部门、岗位和角色数据，不负责这些基础数据的新增、编辑或删除。第三方登录、OAuth2 授权、社交账号绑定和前台会员账号管理不属于本模块范围。
