# kb-friendly SRS 改写 Prompt

## 角色

你负责把事实草稿改写为知识库友好的正式 SRS。默认输出模式为 `kb-friendly`。

## 输入

```text
srs-factual-draft.md
source-evidence-map.md
scope-confirmation.md
```

## 输出

```text
srs-kb-friendly.md
```

## 文档结构

必须使用以下章节：

1. 文档概述
2. 模块范围
3. 角色与权限概述
4. 功能需求
5. 字段与输入规则
6. 业务规则
7. 异常处理规则
8. 验收标准
9. 明确排除项
10. 源码依据说明

## 改写规则

### 1. 连续段落优先

字段规则、权限规则、异常处理和验收标准优先使用段落或短列表，不使用复杂表格承载唯一关键信息。

### 2. 标题层级稳定

每个 FR 使用固定标题：

```text
### FR-{MODULE}-{NNN} {功能名称}
```

### 3. 编号稳定

FR 编号来自事实草稿，不随意重排。

### 4. 适合检索

关键字段、错误码、权限码、验收标准关键词必须出现在正文中。

### 5. 不新增源码事实

改写只能重组表达，不能新增事实草稿和 evidence 中不存在的内容。

## 功能需求段落模板

```markdown
### FR-{MODULE}-{NNN} {功能名称}

系统应支持……。

该功能的输入包括……。系统应根据……进行校验。

当……时，系统应……。当……不满足时，系统应返回……。

该功能需要……权限。
```

## 验收标准模板

```markdown
#### FR-{MODULE}-{NNN} 验收标准

- 当用户具备……权限并提交有效输入时，系统应……。
- 当输入缺少……时，系统应……。
- 当……不存在或不满足规则时，系统应……。
```

## 禁止事项

- 不要输出复杂大表格。
- 不要把源码类名堆砌成需求描述。
- 不要隐藏排除项。
- 不要写无法追溯到 evidence 的规则。

## 失败条件

- 文档结构不符合默认章节。
- 核心 FR 缺失。
- 关键规则无法在正文检索。
- 出现无 evidence 支撑的确定需求。
