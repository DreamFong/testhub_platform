# Source Facts

## 盘点任务主单

- 任务创建时必须校验任务编码唯一、盘点人有效；当提供盘点方案时，还需校验方案可用。
- 新建任务默认进入草稿状态；若关联方案，则会基于当前方案生成盘点任务行。
- 任务修改仅允许在草稿状态进行；修改后若仍关联方案，会重新生成盘点任务行。
- 任务删除仅允许在草稿状态进行；删除任务前会先删除该任务下的盘点结果与盘点任务行。
- 任务提交仅允许在草稿状态进行，且任务下至少存在一条盘点任务行；提交后状态转为审批中。
- 任务完成仅允许在审批中状态进行；完成后状态转为已完成。
- 已完成或已取消的任务不允许再次取消；取消后状态转为已取消。
- 当任务启用了库存冻结标识时，提交时会冻结相关库存，完成或取消时会解冻相关库存。

## 盘点任务行

- 盘点任务行可由盘点方案自动生成，也可在草稿状态下手工新增、修改、删除。
- 自动生成时，会基于盘点方案参数过滤库存；若为动态盘点，还必须提供开始时间和结束时间。
- 若方案过滤后无库存可盘，则任务行生成失败。
- 自动生成的每条盘点任务行会带出账面数量、仓库/库区/库位/物料/批次等信息，盘点数量初始为 0。
- 新建任务行默认状态为盘亏，待录入盘点数量后再根据账面数量与盘点数量比较结果更新状态。
- 行状态计算口径为：盘点数量大于账面数量时为盘盈，小于时为盘亏，等于时为正常。

## 盘点结果

- 盘点结果新增、修改、删除均要求任务处于盘点中状态。
- 新增盘点结果时，如果未指定任务行，系统会按 taskId + itemId + areaId 尝试匹配既有任务行；若不存在，则自动创建一条账面数量为 0 的任务行。
- 对同一任务行，若其已有大于 0 的盘点数量，则不允许再次录入盘点结果。
- 新增盘点结果后，会同步更新对应任务行的盘点数量与状态。
- 修改盘点结果时，不允许变更关联任务行，只会覆盖更新盘点数量，并同步刷新任务行状态。
- 删除盘点结果后，会对对应任务行执行一次带负值的数量更新，用于回退该行的盘点数量与状态。

## 盘点差异处理

- 差异并未独立建模为“处理单”，而是通过任务行状态表达盘盈、盘亏或正常。
- 当盘点结果没有命中既有任务行时，系统会新建账面数量为 0 的任务行，因此录入正数盘点数量时会被判定为盘盈。
- 删除盘点结果时传入的是原盘点数量的相反数，但任务行更新逻辑是覆盖式写入，而不是基于原值做累加/扣减；这使“负值 count 的业务口径”存在解释空间，需要在风险项中明确暴露。

## 权限与接口层事实

- 任务查询、创建、修改、删除、完成、导出等入口存在显式权限控制。
- 任务行与盘点结果的查询与维护入口复用盘点任务权限能力。
- 权限码、接口路径、控制器方法名均可在 controller 层直接追溯，不应作为主正文表达主体。
