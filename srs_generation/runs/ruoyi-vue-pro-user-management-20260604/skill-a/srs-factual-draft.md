# 用户管理 SRS 事实草稿

## 1. 模块范围

### 1.1 纳入范围

用户管理模块覆盖用户分页查询、列表查询、精简列表、详情、新增、修改、删除、批量删除、重置密码、修改状态、导出、导入模板、导入、免鉴权精简查询和按昵称模糊搜索精简用户。

### 1.2 排除范围

部门管理、角色管理、岗位管理、用户个人中心、用户注册、OAuth2 认证流程和 IM 好友管理流程不纳入本次 SRS。

### 1.3 相邻依赖

用户管理依赖部门、角色、岗位、OAuth2 token、IM 消息等能力，但这些只作为规则或副作用说明，不展开相邻模块需求。

## 2. 功能事实

### FR-USER-001 用户分页查询

系统通过 `GET /system/user/page` 提供用户分页查询。查询条件包括用户账号、手机号、状态、创建时间、部门编号和角色编号。部门编号会扩展为包含子部门的部门集合；角色编号会先转换为用户 ID 集合。返回结果会拼接部门信息。

### FR-USER-002 用户列表查询

系统通过 `GET /system/user/list` 按用户 ID 列表查询用户详情列表。空结果返回空列表，非空结果拼接部门信息。

### FR-USER-003 用户精简列表查询

系统通过 `/list-all-simple` 和 `/simple-list` 返回精简用户列表。传入部门编号时查询部门用户；未传部门编号时只返回启用用户。

### FR-USER-004 用户详情查询

系统通过 `GET /system/user/get` 按 ID 查询用户详情。用户不存在时返回 null，存在时返回包含部门信息的用户详情。

### FR-USER-005 用户新增

系统通过 `POST /system/user/create` 新增用户。新增前检查租户账号配额、用户名唯一、手机号唯一、邮箱唯一、部门有效、岗位有效。新增用户默认启用，密码加密保存，并维护岗位关联。

### FR-USER-006 用户修改

系统通过 `PUT /system/user/update` 修改用户。修改前校验用户存在、用户名唯一、手机号唯一、邮箱唯一、部门有效、岗位有效。修改时不更新密码，并同步维护岗位关联。昵称或头像变化时发送资料更新消息。

### FR-USER-007 用户删除

系统通过 `DELETE /system/user/delete` 删除用户。删除前校验用户存在，删除后清理权限关联和岗位关联。

### FR-USER-008 用户批量删除

系统通过 `DELETE /system/user/delete-list` 批量删除用户，并逐个清理权限关联和岗位关联。

### FR-USER-009 重置用户密码

系统通过 `PUT /system/user/update-password` 重置用户密码。用户 ID 和新密码必填，密码长度 4-16 位。重置前校验用户存在，保存时加密密码。

### FR-USER-010 修改用户状态

系统通过 `PUT /system/user/update-status` 修改用户状态。状态必须属于 CommonStatusEnum。禁用用户时，系统删除该用户后台 OAuth2 token。

### FR-USER-011 用户导出

系统通过 `GET /system/user/export-excel` 导出用户。导出使用分页查询条件，但设置为不分页，输出 UserRespVO 对应 Excel 字段。

### FR-USER-012 用户导入模板下载

系统通过 `GET /system/user/get-import-template` 下载导入模板。模板包含示例用户，字段来自 UserImportExcelVO。

### FR-USER-013 用户导入

系统通过 `POST /system/user/import` 导入用户 Excel。导入列表不能为空，初始化密码配置不能为空。系统逐行校验字段和业务规则，用户名不存在时创建，用户名存在且支持更新时更新，否则记录失败。

### FR-USER-014 免鉴权精简用户查询

系统通过 `GET /system/user/get-simple` 按 ID 查询精简用户信息，用户不存在时返回 null。

### FR-USER-015 按昵称模糊搜索精简用户

系统通过 `GET /system/user/list-by-nickname` 按昵称模糊搜索精简用户。昵称为空时返回空列表，非空时 trim 后按昵称匹配。

## 3. 字段事实

用户账号必填，只能由数字和字母组成，长度 4-30，并且唯一。昵称最长 30。邮箱必须符合邮箱格式，最长 50，并且唯一。手机号必须符合手机号规则，并且唯一。新增用户时密码必填，密码长度 4-16；修改用户时通用保存接口不更新密码。状态修改时用户 ID 和状态必填，状态必须属于 CommonStatusEnum。

## 4. 业务规则事实

新增用户需要检查租户账号数上限。新增和修改需要检查用户名、手机号、邮箱唯一性，并校验部门和岗位有效。删除用户需要清理权限和岗位关联。禁用用户需要删除后台 token。导入用户需要读取初始化密码配置，并分别记录创建成功、更新成功和失败明细。

## 5. 权限事实

新增、修改、删除、重置密码、查询、导出和导入均有显式权限码。精简列表、导入模板、免鉴权精简详情和昵称搜索无显式权限注解。

## 6. 异常事实

主要异常包括用户名已存在、手机号已存在、邮箱已存在、用户不存在、导入数据为空、导入初始密码为空、超过租户账号配额和用户已禁用。

## 7. 验收要点草稿

用户分页查询应支持条件过滤和部门子树筛选。新增用户应在合法输入下返回用户 ID，并在重复账号、手机号、邮箱时返回对应错误。修改用户不应更新密码。删除用户应清理权限和岗位关联。禁用用户应删除后台 token。导入用户应返回创建、更新和失败明细。

## 8. 不确定项与风险

无阻断风险。免鉴权精简查询属于用户管理扩展查询能力，但使用场景服务于 IM，不展开 IM 业务流程。
