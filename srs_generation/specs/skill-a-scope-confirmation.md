# Skill A：Scope 自动推断与确认机制

版本：v0.1  
适用范围：Skill A 正式 SRS 生成前置 gate

## 1. 目标

Scope 自动推断与确认机制用于解决“用户只知道目标模块，但不一定完整知道模块范围”的问题。Skill A 必须先从源码推断候选功能范围，再交由用户确认，之后才能进入正式 SRS 生成。

```text

```

## 2. 入口发现规则

### 2.1 从 target_module 搜索 Controller / Router

搜索目标：

- 文件名包含模块关键词的 Controller / Router。
- 路由路径包含模块关键词的接口。
- 类名、注解或方法名与模块关键词相关的入口。

判断规则：

- Controller / Router 通常是功能边界的第一来源。
- 同一 Controller 中的公开接口默认作为候选功能。
- 与目标模块无关的辅助接口应进入相邻能力或排除项。

### 2.2 从 target_module 搜索 Service

搜索目标：

- 与 Controller 直接调用相关的 Service。
- 类名包含模块关键词的 Service / Use Case。
- 被主要入口方法调用的业务校验方法。

判断规则：

- Service 方法用于识别业务规则、状态变更、删除限制、导入导出处理。
- 私有校验方法不单独作为功能需求，但应作为规则依据。

### 2.3 从 target_module 搜索 DTO / VO / Schema

搜索目标：

- Request DTO / ReqVO / Command。
- Response DTO / RespVO / View Object。
- Import / Export VO。
- Page / Query / Filter 对象。

判断规则：

- Request 类型用于字段规则和输入约束。
- Response 类型用于输出信息范围。
- Import / Export 类型用于判断导入导出能力是否存在。

### 2.4 从 target_module 搜索 Entity / DO / Mapper

搜索目标：

- 与模块对应的数据实体。
- Mapper / Repository / DAO。
- SQL / migration / 初始化数据。

判断规则：

- Entity / DO 用于补充字段、状态、默认值和唯一性线索。
- Mapper / SQL 用于补充查询条件、排序、唯一索引和数据约束。

### 2.5 从权限码搜索功能边界

搜索目标：

- 权限注解。
- 权限码常量。
- 菜单初始化数据。

判断规则：

- 权限码经常与功能点一一对应。
- 存在权限码但没有公开入口时，应标记为待确认。

### 2.6 从错误码搜索功能边界

搜索目标：

- ErrorCodeConstants。
- 异常抛出位置。
- 校验方法。

判断规则：

- 错误码用于识别业务规则和异常场景。
- 错误码本身不必然代表独立功能。

## 3. 功能候选归类规则

候选功能应以业务能力表达，而不是直接使用代码方法名。

### 3.1 查询类功能

包括：

- 列表查询。
- 分页查询。
- 条件查询。
- 精简列表查询。
- 下拉选择查询。

归类依据：GET 列表接口、page/list 方法、query/filter DTO。

### 3.2 详情类功能

包括：

- 按 ID 查询详情。
- 当前对象查询。
- 关联详情查询。

归类依据：GET detail/get/{id} 接口、get 方法、RespVO。

### 3.3 新增类功能

包括：

- 新增单个对象。
- 批量新增。
- 导入创建。

归类依据：POST create/add 接口、CreateReqVO、save 方法。

### 3.4 编辑类功能

包括：

- 全量编辑。
- 局部更新。
- 重置密码等专项更新。

归类依据：PUT update 接口、UpdateReqVO、update 方法。

### 3.5 删除类功能

包括：

- 单个删除。
- 批量删除。
- 逻辑删除。
- 禁用类删除替代操作。

归类依据：DELETE 接口、delete/remove 方法、批量 ID 入参。

### 3.6 批量操作

包括：

- 批量删除。
- 批量导入。
- 批量导出。
- 批量状态修改。

归类依据：集合入参、批处理 Service、import/export 方法。

### 3.7 导入导出

包括：

- 数据导入。
- 导入模板。
- 数据导出。

归类依据：Excel VO、文件上传接口、export 接口。

### 3.8 状态流转

包括：

- 启用 / 禁用。
- 审核 / 退回。
- 发布 / 下线。
- 锁定 / 解锁。

归类依据：状态字段、状态更新接口、状态枚举。

### 3.9 配置类功能

包括：

- 模块参数配置。
- 默认值配置。
- 字典 / 枚举配置。

归类依据：配置接口、字典引用、初始化数据。

## 4. 相邻能力识别规则

### 4.1 跨模块调用

当目标模块调用其他模块 Service，但该能力不是本模块公开接口时，应默认列为相邻能力或依赖说明。

### 4.2 共享基础能力

认证、组织架构、角色权限、字典、文件上传等共享能力，除非本轮目标明确要求，否则不展开为本模块功能需求。

### 4.3 只读依赖能力

如果目标模块只读取其他模块数据用于筛选或展示，应标记为依赖说明，不默认纳入功能范围。

### 4.4 可配置但非主线能力

如果源码中存在配置项影响目标模块行为，但配置本身由其他模块维护，应列为相邻能力或外部约束。

### 4.5 待确认相邻能力输出格式

```text
待确认的相邻能力：
- 能力名称：
  - 关联来源：
  - 与目标模块关系：
  - 建议处理：纳入 / 排除 / 仅作为依赖说明
  - 原因：
```

## 5. 用户确认问题

标准确认问题：

```text
请确认以下 scope：

候选纳入范围：
- ...

待确认相邻能力：
- ...

建议排除范围：
- ...

请确认：
1. 候选纳入范围是否全部纳入？
2. 待确认相邻能力中哪些需要纳入？哪些需要排除？
3. 是否存在遗漏功能？
4. 是否有必须明确排除的功能？
```

## 6. Gate 状态

### confirmed

用户确认候选范围无修改，可进入源码事实抽取。

### confirmed_with_changes

用户补充或排除了部分能力。Skill A 应记录变更后的最终范围，再进入源码事实抽取。

### blocked

以下情况应 blocked：

- 目标模块入口无法定位。
- 用户未确认范围。
- 范围争议会影响 SRS 主体结构。
- 需要补充 entry_files 或业务边界说明。

## 7. 重新推断触发条件

以下情况必须重新推断 scope：

- target_module 修改。
- entry_files 大幅变化。
- 用户补充了新的核心功能。
- 用户排除了原候选范围中的核心入口。
- 新发现源码入口会改变功能列表。
