# Skill A 规范固化任务清单

## 目标

将 Skill A 从讨论稿收敛为正式规范，明确它如何从源码逆向生成 SRS 文档，以及如何判断文档是否可进入 Skill B。

## 1. 职责边界

- [ ] 写明 Skill A 的核心职责：源码事实抽取、SRS 生成、PDF 生成、文档质量评审
- [ ] 写明 Skill A 不负责 RAGFlow 建库
- [ ] 写明 Skill A 不负责 chunk 质量评估
- [ ] 写明 Skill A 不负责 retrieval gate
- [ ] 写明 Skill A 不负责执行约束增强
- [ ] 写明 Skill A 与 Skill B / Skill C 的边界关系

完成标准：读者能明确判断一个任务是否属于 Skill A。

## 2. 输入契约

- [ ] 定义 `source_project` 为必填输入
- [ ] 定义 `target_module` 为必填输入
- [ ] 定义 `entry_files` 为选填输入
- [ ] 定义 `scope_hint` 为选填输入
- [ ] 定义 `reference_srs` 为选填输入
- [ ] 定义 `output_mode` 为选填输入
- [ ] 定义 `domain_hints` 为选填输入
- [ ] 明确 `scope_hint` 只是范围提示，不是事实来源
- [ ] 明确 `reference_srs` 只用于风格参考，不覆盖源码事实

完成标准：输入参数可以直接转化为执行表单或命令参数。

## 3. Scope 自动推断与确认

- [ ] 定义候选 scope 推断的数据来源
- [ ] 定义候选纳入范围的输出格式
- [ ] 定义待确认相邻能力的输出格式
- [ ] 定义用户确认问题模板
- [ ] 定义 `confirmed` 状态
- [ ] 定义 `confirmed_with_changes` 状态
- [ ] 定义 `blocked` 状态
- [ ] 明确未完成 scope confirm 不进入正式 SRS 生成

完成标准：即使用户只提供模块名，Skill A 也知道先推断范围再请求确认。

## 4. 输出契约

- [ ] 定义最终 SRS Markdown 产物
- [ ] 定义最终 SRS PDF 产物
- [ ] 定义 `source_evidence_map` 产物
- [ ] 定义 `self_review_report` 产物
- [ ] 定义 `independent_review_report` 产物
- [ ] 定义 `risk_items` 产物
- [ ] 定义输出文件命名建议
- [ ] 定义输出目录结构建议

完成标准：Skill A 的每次执行都有稳定产物集合。

## 5. 文档模板

- [ ] 固化“文档概述”章节
- [ ] 固化“模块范围”章节
- [ ] 固化“角色与权限概述”章节
- [ ] 固化“功能需求”章节
- [ ] 固化“字段与输入规则”章节
- [ ] 固化“业务规则”章节
- [ ] 固化“异常处理规则”章节
- [ ] 固化“验收标准”章节
- [ ] 固化“明确排除项”章节
- [ ] 固化“源码依据说明”章节
- [ ] 定义 FR 编号规则

完成标准：不同模块生成的 SRS 结构稳定，便于评审和进入知识库。

## 6. 评分模型

- [ ] 定义功能覆盖度评分标准
- [ ] 定义源码准确度评分标准
- [ ] 定义规则完整度评分标准
- [ ] 定义需求表达质量评分标准
- [ ] 定义知识库友好度评分标准
- [ ] 定义总分 25 分模型
- [ ] 定义每项 1～5 分判定说明

完成标准：评审 Agent 和人工复核可以使用同一套评分口径。

## 7. 硬性不合格项

- [ ] 明确编造源码中不存在内容为 fail
- [ ] 明确核心功能缺失为 fail
- [ ] 明确关键规则写反为 fail
- [ ] 明确文档结构不可用为 fail
- [ ] 明确 PDF 文本层不可提取为 fail
- [ ] 明确关键结论无法提供源码依据为 fail

完成标准：不合格边界明确，不因总分高而放过致命问题。

## 8. Gate 与 handoff

- [ ] 定义 `pass`
- [ ] 定义 `conditional pass`
- [ ] 定义 `fail`
- [ ] 定义触发人工复核的条件
- [ ] 定义 Skill A 向 Skill B 交接的最小文件集合
- [ ] 明确默认交接 `kb-friendly` 版本

完成标准：Skill A 的输出能被 Skill B 稳定消费。
