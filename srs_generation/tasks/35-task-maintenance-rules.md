# 任务清单维护规则

## 目标

保证任务清单后续可维护，而不是一次性文档。

## 勾选规则

- [ ] 只有实际完成的任务才能勾选
- [ ] 讨论确认但未落文件的任务不勾选
- [ ] 文件创建完成但内容未评审的任务不勾选为完成
- [ ] 被后续决策废弃的任务应标注原因或移除

## 更新规则

- [ ] 当 Skill A spec 改动时，同步检查 Skill A 相关任务
- [ ] 当 scope 机制改动时，同步更新 scope 相关任务
- [ ] 当输出产物改动时，同步更新 artifact 与 handoff 任务
- [ ] 当 gate 规则改动时，同步更新 quality gates 和 review 任务
- [ ] 当新增样本验证结论时，同步更新风险登记表

## 文件拆分规则

- [ ] 一个文件只覆盖一个主题
- [ ] 任务过长时拆分新文件
- [ ] 总览文件只做索引，不堆详细任务
- [ ] 决策类内容放入 `08-open-decisions.md`
- [ ] 风险类内容放入 `17-risk-register.md`

## 命名规则

- [ ] 使用两位数字前缀排序
- [ ] 使用小写英文和连字符
- [ ] 文件名表达主题
- [ ] 不按日期命名任务文件

## 关闭规则

当某个阶段完成后，应更新：

- [ ] 对应任务文件
- [ ] [18-done-criteria.md](18-done-criteria.md)
- [ ] [19-task-index-by-priority.md](19-task-index-by-priority.md)
- [ ] [20-traceability-matrix.md](20-traceability-matrix.md)

## 建议

每完成一个阶段，都先更新任务清单，再继续下一阶段，避免实际进度与计划脱节。
